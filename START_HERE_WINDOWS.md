# FORMA: полное развёртывание на Windows с Docker Desktop

**Автоматический вариант:** распакуйте проект и запустите **START-FORMA.cmd**. Он выполнит основную настройку, предложит создать администратора и ввести API-ключ, затем откроет приложение. [Краткая инструкция](ONE_CLICK_WINDOWS.md). Ниже остаются полные ручные шаги и обслуживание.

Инструкция от 24 октября 2026. Основной сценарий: один Windows-компьютер работает сервером, около 10 учеников открывают приложение с других компьютеров в одной локальной сети центра. Генерацию выполняет Meshy; видеокарта на сервере не нужна. Домен и проброс портов в интернет для этого сценария не требуются.

В комплект добавлены `compose.classroom.yaml`, `Caddyfile.classroom`, `.env.classroom.example` и команда `forma.cmd`. Это отдельный проект Docker **forma-classroom** с собственной базой и файлами. Старое демо **forma-local** не удаляется. Его аккаунты, заявки и модели автоматически не переносятся.

Если вам нужно сохранить уже существующие реальные данные, сначала сделайте резервную копию старой базы и файлов и спланируйте перенос. Не считайте распаковку ZIP переносом данных: ZIP содержит исходники.

## 1. Подготовьте компьютер и сеть

1. Запустите Docker Desktop и дождитесь готовности движка.
2. Docker должен работать с **Linux containers**. Python, PostgreSQL и Redis отдельно на Windows устанавливать не нужно.
3. Компьютер-сервер и ученические компьютеры должны видеть друг друга в сети центра. Гостевая Wi-Fi-сеть с изоляцией клиентов не подходит.
4. Интернет необходим серверу: сначала для загрузки Docker-образов и зависимостей, затем для работы с Meshy.
5. Во время занятий сервер должен быть включён и не переходить в сон. В Docker Desktop можно включить запуск при входе пользователя в Windows. После перезагрузки дождитесь запуска Docker и выполните команду `up`, приведённую ниже.

Проверка в PowerShell:

```powershell
docker version
docker compose version
docker info --format '{{.OSType}}'
```

Последняя команда должна вернуть `linux`. Если Docker сообщает, что не может подключиться к движку, сначала запустите Docker Desktop; переустановка приложения FORMA это не исправляет.

## 2. Скачайте и распакуйте актуальный проект

Скачайте новый архив `FORMA-meshy-classroom.zip` из этого чата. Нужна версия, в которой уже есть `forma.cmd` и `compose.classroom.yaml`.

Например, распакуйте так:

```text
C:\FORMA\meshy-classroom\
    forma.cmd
    compose.classroom.yaml
    Caddyfile.classroom
    .env.classroom.example
    Dockerfile
    manage.py
    ...
```

Откройте PowerShell и перейдите в папку:

```powershell
Set-Location 'C:\FORMA\meshy-classroom'
```

Если выбрали другое место, используйте свой путь. Все команды `forma.cmd` далее выполняются из этой папки. Обёртка сама выбирает нужные файлы Compose и окружения.

## 3. Узнайте локальный IP компьютера-сервера

В PowerShell выполните:

```powershell
ipconfig
```

Найдите IPv4-адрес активного Ethernet или Wi-Fi адаптера. Пример для инструкции — **192.168.1.50**.

Не используйте адрес адаптера Docker, WSL или `127.0.0.1`. IP должен относиться к сети, в которой находятся ученики. Лучше закрепить этот адрес за сервером в DHCP-настройках роутера центра. Если IP изменится, потребуется обновить настройки и адрес, выдаваемый детям.

Далее **везде заменяйте 192.168.1.50 на свой реальный IP**.

## 4. Создайте файл окружения

Для первого развёртывания скопируйте шаблон:

```powershell
if (-not (Test-Path -LiteralPath '.env.classroom')) {
    Copy-Item -LiteralPath '.env.classroom.example' -Destination '.env.classroom'
}
notepad .env.classroom
```

В Проводнике включите отображение расширений файлов. Нужное имя — **.env.classroom**, без `.txt` на конце. В этом профиле читается именно `.env.classroom`, а не старый `.env`.

Получите два случайных секрета:

```powershell
docker run --rm python:3.12-slim python -c "import secrets; print(secrets.token_hex(32)); print(secrets.token_hex(32))"
```

Первый запуск скачает официальный Python-образ. Команда напечатает две строки. Запишите первую как `DJANGO_SECRET_KEY`, вторую как `POSTGRES_PASSWORD`.

Содержимое `.env.classroom` должно выглядеть так:

```dotenv
CLASSROOM_HOST=192.168.1.50
DJANGO_SECRET_KEY=ПЕРВАЯ_СЛУЧАЙНАЯ_СТРОКА
POSTGRES_PASSWORD=ВТОРАЯ_СЛУЧАЙНАЯ_СТРОКА
APP_TIME_ZONE=Asia/Yekaterinburg

MESHY_MODE=demo
MESHY_API_KEY=
MESHY_AI_MODEL=meshy-7.1
MESHY_ASSET_HOSTS=assets.meshy.ai
```

IP указывается без `https://` и без номера порта. Секреты из примера нужно заменить. Удобнее использовать сгенерированные шестнадцатеричные строки: в них нет символов, требующих экранирования в Compose.

Начинаем с `demo`, чтобы проверить систему без затрат кредитов. При этом в сетевой конфигурации DEBUG выключен и используются обычные логины и пароли; входа по демо-кнопкам нет. Команду `seed_demo` здесь выполнять не нужно.

Не меняйте `POSTGRES_PASSWORD` простым редактированием файла после создания базы: это не изменяет пароль уже существующего пользователя PostgreSQL. Первоначальные значения сохраните для обслуживания и восстановления.

## 5. Соберите и запустите приложение

Проверьте конфигурацию без вывода секретов:

```powershell
.\forma.cmd config --quiet
```

Затем запустите:

```powershell
.\forma.cmd up -d --build --wait --wait-timeout 600
```

При первом запуске скачиваются образы и Python-пакеты. Создаются PostgreSQL, Redis, сервер приложения, worker, планировщик и Caddy для HTTPS. Автоматически применяются миграции и создаются стили и лимиты центра.

Проверьте:

```powershell
.\forma.cmd ps
```

Все шесть сервисов — `db`, `redis`, `web`, `worker`, `beat`, `proxy` — должны быть запущены. У `db`, `redis` и `web` должно быть состояние `healthy`; у остальных достаточно `running`.

Если что-то не поднялось:

```powershell
.\forma.cmd logs --tail=150 web worker beat proxy
```

Не запускайте одновременно вторую копию `beat` для этого же проекта.

## 6. Настройте доверие к HTTPS на серверном компьютере

Для локальной сети Caddy создаёт собственный центр сертификации. Доверие к его открытому сертификату нужно установить на каждом компьютере, с которого будут входить в приложение.

На сервере скопируйте только открытый сертификат:

```powershell
.\forma.cmd cp proxy:/data/caddy/pki/authorities/local/root.crt .\forma-root.crt
```

Затем добавьте его в хранилище доверенных корневых сертификатов текущего пользователя Windows:

```powershell
certutil -user -addstore Root .\forma-root.crt
```

Если Windows попросит подтвердить добавление, проверьте, что это сертификат именно вашего сервера FORMA. Эта операция означает доверие сертификатам, выдаваемым его локальным центром сертификации. Приватный ключ центра остаётся в Docker volume; детям передаётся только файл `forma-root.crt`, никаких `.key` файлов.

Перезапустите Edge/Chrome и откройте:

```text
https://192.168.1.50:8443
```

Используйте именно IP из `CLASSROOM_HOST`. Здесь не подходит старый адрес `http://localhost:8010`. Если сертификат ещё не появился, проверьте журнал `proxy` и повторите копирование после его успешного запуска. Если браузер показывает ошибку сертификата, исправьте установку доверия и соответствие IP; обходить предупреждение для работы детей не нужно.

## 7. Разрешите подключения учеников в брандмауэре Windows

Убедитесь, что доверенная сеть центра имеет в Windows профиль **«Частная»**. Откройте PowerShell **от имени администратора** и выполните один раз:

```powershell
New-NetFirewallRule -DisplayName 'FORMA HTTPS 8443' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8443 -Profile Private -RemoteAddress LocalSubnet
```

Правило разрешает подключения к приложению из локальной подсети. На роутере не нужен проброс портов в интернет. База, Redis и Gunicorn наружу не публикуются; опубликован только HTTPS-прокси на адресе сервера и порту 8443.

Если сеть управляется централизованно и профиль или брандмауэр задаёт администратор организации, передайте ему адрес сервера и требуемый TCP-порт 8443.

## 8. Создайте администратора

В обычном PowerShell из папки проекта выполните:

```powershell
.\forma.cmd exec web python manage.py createsuperuser
```

Задайте логин, email при необходимости и пароль. При вводе пароля символы не показываются — это нормально. Пароль хранится в базе в виде хеша; в файл окружения он не записывается.

Откройте админку:

```text
https://192.168.1.50:8443/admin/
```

Войдите с созданными данными. Если вы раньше входили в старое демо, его учётная запись в новой базе не используется: здесь нужен только что созданный администратор.

## 9. Создайте преподавателя и учеников

Для первоначальной проверки администратор может сам выполнять роль преподавателя: откройте главную страницу приложения, и ему будут доступны заявки, ученики и настройки.

Для отдельного преподавателя:

1. В Django Admin откройте «Пользователи» → «Добавить».
2. Задайте логин и пароль, сохраните пользователя.
3. Откройте его карточку и добавьте в группу **«Преподаватели»**.
4. Оставьте пользователя активным и сохраните.

Для обычного кабинета преподавателя флаг `is_staff` не требуется. Если преподавателю нужен доступ к Django Admin, права на эту админку назначаются отдельно.

Выйдите из администратора, войдите преподавателем на главной странице, откройте **«Ученики»** и создайте аккаунты детей. Можно использовать имена или псевдонимы и отдельные логины. Не выдавайте детям аккаунт администратора или преподавателя.

Пароль ученика можно менять через Django Admin; ребёнок также может сменить свой известный пароль в личном кабинете. Разные роли можно проверять в разных профилях браузера или в обычном и приватном окне. Вкладки одного профиля используют общую сессию.

## 10. Выполните учебную проверку без Meshy

Пока оставьте `MESHY_MODE=demo`.

1. Войдите обычным учеником и отправьте фото/рисунок с выбранным стилем.
2. Войдите преподавателем в другом профиле или после выхода из ученика.
3. Одобрите заявку и убедитесь, что она проходит очередь, генерацию и сохранение.
4. Откройте готовый проект учеником. Должны работать 3D-просмотр и скачивание FBX/ZIP.
5. Создайте вторую заявку и верните её с комментарием. Ученик должен увидеть причину.
6. Проверьте, что при одной незавершённой заявке новая не создаётся.

В демо выдаётся учебный кристалл, а не модель по фото. В этом тесте нет расхода кредитов. Переходы очереди занимают некоторое время: beat проверяет задания примерно каждые 15 секунд.

Дополнительно можно выполнить автоматические тесты на PostgreSQL этого развёртывания:

```powershell
.\forma.cmd exec -e MESHY_MODE=demo -e MESHY_API_KEY= web python manage.py test studio.tests
```

Они используют отдельную тестовую базу, временные файлы, изолированный кеш и замоканные вызовы Meshy. В отличие от прежнего тестирования на SQLite, здесь могут выполняться и два теста реальных блокировок PostgreSQL. Выполняйте это до занятий, когда приложение не используется учениками.

## 11. Подключите настоящий Meshy

Создайте API-ключ в кабинете Meshy. Нужен именно API-ключ. Проверьте доступность API, кредитов и разрешённых параллельных задач вашего аккаунта.

Откройте **.env.classroom**:

```powershell
notepad .env.classroom
```

Замените только две строки:

```dotenv
MESHY_MODE=live
MESHY_API_KEY=ВАШ_НАСТОЯЩИЙ_API_КЛЮЧ
```

Секрет Django и пароль PostgreSQL оставьте прежними. Дождитесь завершения всех учебных заявок и примените новое окружение:

```powershell
.\forma.cmd up -d --build --wait --wait-timeout 600
```

Обычный `restart` не перечитывает переменные окружения контейнеров; используйте `up`.

Проверьте режим, не выводя сам ключ:

```powershell
.\forma.cmd exec web python manage.py shell -c "from django.conf import settings; print('Mode:', settings.MESHY_MODE); print('Key configured:', bool(settings.MESHY_API_KEY))"
```

Ожидается `Mode: live` и `Key configured: True`. В интерфейсе преподавателя на странице настроек тоже отображается состояние подключения.

С этого момента одобрения преподавателя разрешают реальные платные генерации. Первую заявку выполните сами: проверьте получение модели, скачайте ZIP и импортируйте FBX с текстурами в Unity 6 URP. Внутри ZIP находится инструкция назначения материалов URP/Lit; сам FBX не гарантирует автоматическую настройку URP-шейдера.

Учебные готовые модели остаются демонстрационными. Для проверки настоящего Meshy подайте и одобрите новую заявку.

## 12. Подключите ученические компьютеры

На каждом ученическом Windows-компьютере:

1. Подключитесь к сети центра, в которой доступен компьютер-сервер.
2. Скопируйте с него файл **forma-root.crt**. Исходники, Docker и API-ключ детям не нужны.
3. От имени того Windows-пользователя, под которым будет работать ученик, установите открытый сертификат:

```powershell
certutil -user -addstore Root 'C:\Путь\к\forma-root.crt'
```

4. Перезапустите Edge/Chrome и откройте `https://192.168.1.50:8443` с вашим реальным IP.
5. Войдите под индивидуальным ученическим логином и паролем. Сохраните адрес в закладках.

Команда устанавливает доверие только для текущего пользователя Windows. Если дети работают под разными Windows-пользователями на одном ПК, доверие нужно настроить для каждого или централизованно через администратора. Для Firefox при необходимости настройте доверие к этому CA отдельно.

Если страница с ученического ПК не открывается, выполните на нём:

```powershell
Test-NetConnection 192.168.1.50 -Port 8443
```

`TcpTestSucceeded: True` означает, что TCP-порт доступен. Если False — проверяйте IP, профиль сети, брандмауэр, включённость сервера и изоляцию Wi-Fi. Если TCP доступен, но браузер сообщает о сертификате, проверяйте установленный CA и точное соответствие адреса.

## 13. Настройте лимиты центра

В кабинете преподавателя откройте **«Настройки центра»**:

- Параллельные генерации: до **10**.
- Дневной лимит заявок ребёнка: по умолчанию **5**.
- Месячный лимит одобрений центра: по умолчанию **100**, измените под свой бюджет.
- «Разрешить отправку в Meshy»: включено для работы, выключается для паузы новых запусков.

Одна незавершённая заявка на ученика действует независимо от дневного лимита. Состояния ожидания проверки, очереди, отправки, генерации, сохранения и ручной сверки блокируют следующую заявку. Готовность, возврат или окончательная ошибка разрешают новую. Заявки запускаются по порядку одобрения.

Количество worker-процессов `2` не ограничивает число внешних генераций двумя: Meshy асинхронный, и приложение может отслеживать 10 генераций при двух фоновых процессах.

## 14. Ежедневная работа и обновление

Перед занятием:

```powershell
Set-Location 'C:\FORMA\meshy-classroom'
.\forma.cmd up -d --wait --wait-timeout 600
.\forma.cmd ps
```

После занятия при необходимости:

```powershell
.\forma.cmd stop
```

Остановка сохраняет данные. Не используйте `down -v` для обычной остановки: этот флаг удаляет именованные volumes, включая базу, модели и сертификаты.

Для новой версии исходников сначала сделайте резервную копию. Скопируйте новые файлы в ту же папку, сохранив `.env.classroom`, затем:

```powershell
.\forma.cmd up -d --build --wait --wait-timeout 600
```

Новая версия должна использовать то же имя Docker-проекта и те же volumes. Архив проекта не содержит `.env.classroom`, загруженных фото или базы данных.

## 15. Резервное копирование

Минимум нужны PostgreSQL, volume с `media` и сохранённый `.env.classroom`. На новом сервере также понадобится восстановить HTTPS-настройки или заново выдать доверенный сертификат клиентам. Папку резервных копий храните отдельно от Docker-диска, например на защищённом диске центра.

Для согласованной копии дождитесь завершения активных генераций. Из папки проекта выполните:

```powershell
$backupPath = Join-Path 'backups' (Get-Date -Format 'yyyy-MM-dd-HHmmss')
New-Item -ItemType Directory -Path $backupPath -Force | Out-Null

# На время копирования закрываем вход и останавливаем фоновые изменения.
# web остаётся запущен для чтения файлов, но наружу без proxy недоступен.
.\forma.cmd stop proxy worker beat

.\forma.cmd exec -T db pg_dump -U studio -d studio -Fc -f /tmp/forma-db.dump
.\forma.cmd cp db:/tmp/forma-db.dump "$backupPath\database.dump"

.\forma.cmd exec -T web tar -czf /tmp/forma-media.tgz -C /app media
.\forma.cmd cp web:/tmp/forma-media.tgz "$backupPath\media.tgz"

Copy-Item -LiteralPath '.env.classroom' -Destination (Join-Path $backupPath '.env.classroom')

.\forma.cmd up -d --wait --wait-timeout 600
```

Проверьте успешность каждой команды; при ошибке не считайте копию полной. `.env.classroom` в этой копии содержит API-ключ и секреты — храните его с доступом только у администратора. Команды не используют перенаправление бинарного дампа через PowerShell, которое могло бы повредить файл в старых версиях оболочки.

Восстановление базы и файлов выполняется согласованно, до допуска учеников. Не удаляйте рабочие volumes ради проверки копии; восстановление лучше отрабатывать в отдельном экземпляре.

## 16. Если возникла проблема

| Симптом | Что проверить |
|---|---|
| `forma.cmd` просит создать `.env.classroom` | Имя файла, отсутствие `.txt`, нужная папка |
| Docker не подключается к движку | Docker Desktop запущен, выбран Linux engine |
| Ошибка привязки IP или порта | `CLASSROOM_HOST` совпадает с текущим IPv4 Windows; порт 8443 свободен |
| `web` не становится healthy | Журнал web/db, заполненный секрет, подключение к PostgreSQL |
| `password authentication failed` | После первого запуска был изменён пароль в env без изменения роли PostgreSQL |
| Страница открывается на сервере, но не у детей | Брандмауэр, частная сеть, одна подсеть, отсутствие изоляции Wi-Fi |
| Ошибка HTTPS | Установлен именно CA текущего сервера; адрес совпадает с CLASSROOM_HOST |
| Принятая заявка стоит в очереди | worker/beat запущены, отправка разрешена, есть свободные слоты, нет старой заявки впереди |
| Вместо фото выдаётся кристалл | Это demo-режим либо старая демо-задача; проверьте live и подайте новую заявку |
| Meshy отклонил ключ/кредиты | Правильный API-ключ, API-доступ и баланс Meshy |
| «Нужна проверка отправки» | Преподаватель сверяет API-историю Meshy; не отправляйте платную задачу повторно вслепую |
| Не получается войти другой ролью | Выйдите из текущего кабинета; вкладки одного профиля делят сессию |
| Не получается создать вторую заявку | Первая ещё незавершена; это предусмотренное ограничение |

Сбор журналов:

```powershell
.\forma.cmd logs --tail=150 db web worker beat proxy
```

Состояние приложения:

```powershell
.\forma.cmd exec web python manage.py check
```

Не публикуйте содержимое `.env.classroom` и полный вывод `docker compose config`: там могут быть секреты. Для проверки синтаксиса предусмотрен `config --quiet`.

## 17. Если понадобится доступ из дома или через интернет

Этот вариант предназначен для сети центра. Для публичного адреса используйте отдельную production-конфигурацию `compose.yaml` с доменом и публичным HTTPS либо согласованный защищённый доступ к сети центра. Простое открытие локального порта в роутере не заменяет настройку публичного развёртывания.

Развёртывание через `compose.yaml`, старое локальное демо и новый сетевой профиль имеют разные Docker-проекты. При переходе между ними данные нужно переносить явно; не ожидайте, что они автоматически используют одну базу.

## Проверено и что остаётся проверить на вашем ПК

Конфигурации Compose проверены на синтаксис. После подготовки сетевого профиля локально пройдены 36 тестов; два теста реальной конкуренции PostgreSQL пропущены на SQLite и могут быть запущены в Docker командой из раздела 10. Контракт Meshy и схема локального HTTPS сверены с официальной документацией.

Docker-служба на машине разработки не запущена. Поэтому запуск контейнеров, выпуск сертификата новым профилем, подключение ученических ПК и реальный вызов Meshy на вашем сервере пока не проверены. Перед первым занятием выполните учебную проверку, одну реальную генерацию и импорт FBX в установленный Unity 6 URP.
