# FORMA — учебная 3D-мастерская

**Запуск с другого компьютера:** установите Git и Docker Desktop (Linux containers), затем выполните в PowerShell:

```powershell
git clone https://github.com/PaladinAlexandr/forma-meshy-classroom.git
cd forma-meshy-classroom
.\START-FORMA-HTTP.cmd
```

Скрипт соберёт Docker-образы, создаст настройки, предложит создать администратора и ввести API-ключ Meshy (или Enter для демо). Ученики открывают показанный адрес `http://IP-СЕРВЕРА:8010`. Устанавливать приложение на ученические компьютеры не нужно.

**Текущий режим для локальной сети — HTTP без сертификатов.** Используйте его в доверенной сети центра: пароли и фотографии передаются без шифрования. [Запуск и обновление из GitHub](GITHUB_SETUP.md), [HTTP на Windows](HTTP_WINDOWS.md).

**HTTPS:** отдельный запуск `START-FORMA.cmd` использует локальный сертификат Caddy; инструкция — [ONE_CLICK_WINDOWS.md](ONE_CLICK_WINDOWS.md). Для публичного сервера с доменом предусмотрен `compose.yaml`. Режимы локальной сети используют общие данные проекта `forma-classroom`.

Приложение для одного учебного центра: ученики загружают фото или описывают идею текстом и сначала получают картинку; преподаватель одобряет заявку или возвращает её с объяснением; сервер отправляет одобренные заявки через один API-аккаунт Meshy, отслеживает генерацию и сохраняет результат. Интерфейс на русском, адаптирован для компьютера и телефона.

**Тип модели и анимации:** ученик выбирает гуманоид / животное / предмет. После готовности гуманоиду можно добавить ожидание, ходьбу и бег, с отдельным одобрением преподавателя. Результат — FBX с анимацией и ZIP для Unity 6 URP. Животные и предметы создаются без анимаций. Подробности, ограничения API и обновление — [ANIMATIONS.md](ANIMATIONS.md).

## Выбранный стек

| Часть | Решение | Почему |
|---|---|---|
| Сервер и интерфейс | Python, Django 5.2 LTS, HTML/CSS, небольшой JavaScript | Готовая авторизация, права, формы, CSRF и админка; единый проект без отдельного SPA |
| База | PostgreSQL 16 | Транзакции и блокировки для одобрений, квот и очереди |
| Фоновые задания | Celery + Redis | Генерация продолжается при закрытом браузере; состояние хранится в PostgreSQL |
| Файлы | Закрытое файловое хранилище в Docker volume | Фото и модели доступны через сервер с проверкой владельца; можно заменить Django storage на S3 |
| 3D-просмотр | Локальная копия Google model-viewer 4.1.0 | Вращение и масштабирование GLB в браузере |
| Запуск | Docker Compose, Gunicorn, Caddy | Автоматический HTTPS для собственного домена, единый сервер центра |

Для небольшого учебного центра этот стек проще в обслуживании, чем отдельные React-приложение и API. SQLite и команда `runqueue` предусмотрены только для локальной разработки. Продакшен требует PostgreSQL.

## Быстро посмотреть на Windows

Если установлен Docker Desktop, используйте отдельную [инструкцию запуска через Docker на Windows](WINDOWS_DOCKER.md). Установка Python на Windows для этого варианта не требуется. Конфигурация `compose.windows.yaml` открывает приложение только на этом компьютере по адресу http://localhost:8010.

Нужен Python 3.11 или новее. В каталоге проекта:

```powershell
.\run-demo.ps1
```

Откройте **http://127.0.0.1:8010**. Нажмите «Я преподаватель» или «Я ученик». Аккаунты демонстрации не имеют пригодных для входа паролей; кнопки доступны только при `DJANGO_DEBUG=1` и `MESHY_MODE=demo`. Для переключения роли выйдите из текущего кабинета.

Сценарий проверки:

1. Войдите учеником и создайте проект: название, реальное фото/рисунок, стиль и подтверждение об отсутствии личной информации на фото.
2. Выйдите и войдите преподавателем. Откройте заявку и одобрите либо верните её с комментарием.
3. Вновь войдите учеником. Видны решение, комментарий и ход генерации. При успешном завершении доступны 3D-просмотр, FBX и ZIP с текстурами.

В демо вместо обращения к Meshy через примерно 30 секунд выдаётся один и тот же учебный кристалл. Это явно указано в интерфейсе. Кредиты не расходуются; результат не пытается воспроизвести загруженный рисунок. Изображения на демо-карточках нарисованы программно и не являются результатами Meshy.

### Ручной запуск (Windows, Linux, macOS)

```text
python -m venv .venv
# Активируйте .venv для вашей оболочки
python -m pip install -r requirements.lock
python manage.py migrate
python manage.py seed_demo
python manage.py runserver 127.0.0.1:8010
```

Во втором терминале с тем же окружением:

```text
python manage.py runqueue
```

Без фоновой команды одобренные заявки останутся в очереди. Не запускайте `runqueue` одновременно с Celery в продакшене.

## Подключение реального Meshy

Создайте `.env` по образцу `.env.example` и задайте:

```dotenv
MESHY_MODE=live
MESHY_API_KEY=ваш_ключ
MESHY_AI_MODEL=meshy-7.1
```

Перезапустите web, worker и beat после изменения окружения. Ключ не вводится в клиентский интерфейс, не сохраняется в базе и не включается в архив проекта. Не передавайте его детям и не коммитьте `.env`.

Используется `POST https://api.meshy.ai/openapi/v1/image-to-3d` с `image_url` в формате Data URI, `texture_prompt`, `moderation=true`, `enable_pbr=true`, `texture_resolution="2k"`, `target_formats=["glb","fbx"]`. Фото не требуется публиковать в интернете. Статус читается через `GET` того же ресурса с ID задачи. Ожидаемые состояния провайдера: `PENDING`, `IN_PROGRESS`, `SUCCEEDED`, `FAILED`, `CANCELED`.

**Форма и промпт:** ученик выбирает фото или путь «текст → картинка → 3D». Текстовый промпт (до 800 символов, в том числе по-русски) поступает преподавателю; после одобрения сервер вызывает Text to Image API Meshy. Картинка сохраняется локально, затем ученик выбирает её для 3D или завершает проект. Выбор для 3D возвращает проект преподавателю на отдельное одобрение. В Image to 3D геометрию задаёт изображение, а texture_prompt задаёт поверхность. При загрузке фото свой текстовый промпт заменяет шаблон текстуры; при создании картинки выбранный стиль применяется к текстуре будущей модели. Заметка преподавателю не отправляется в API. Промпты фиксируются при подаче заявки.

Модель генерации изображения по умолчанию: nano-banana (MESHY_IMAGE_MODEL). Картинка и 3D оплачиваются как две отдельные задачи Meshy; сумма показывается, когда известны обе стоимости. Лимит центра считает проекты по первому одобрению, второй этап не списывает ещё одно одобрение. Оба этапа используют общую очередь из максимум 10 слотов. Готовая картинка освобождает слот Meshy, но блокирует новую заявку этого ученика до завершения проекта. Подробнее: [TEXT_TO_IMAGE_UPDATE.md](TEXT_TO_IMAGE_UPDATE.md).

**Подписка:** перед боевым запуском проверьте доступность API и кредитов в вашем аккаунте Meshy. Приложение не предполагает, что наличие веб-подписки автоматически обеспечивает любые API-лимиты. Точную стоимость определяет Meshy; лимит центра считает одобрения, а не стоимость в кредитах. Реальные `consumed_credits` отображаются после завершения.

## Развёртывание центра

Понадобятся сервер с Docker Compose, домен и DNS-запись на сервер. Скопируйте `.env.example` в `.env`, заполните production-поля. Например:

```dotenv
DJANGO_DEBUG=0
APP_DOMAIN=classroom.example.org
DJANGO_ALLOWED_HOSTS=classroom.example.org
CSRF_TRUSTED_ORIGINS=https://classroom.example.org
DJANGO_SECRET_KEY=<случайный ключ от 40 символов>
POSTGRES_PASSWORD=<случайный пароль БД>
POSTGRES_DB=studio
POSTGRES_USER=studio
MESHY_MODE=live
MESHY_API_KEY=<ключ Meshy>
MESHY_AI_MODEL=meshy-7.1
```

Для генерации секрета: `python -c "import secrets; print(secrets.token_urlsafe(64))"`.

```text
docker compose up -d --build
docker compose exec web python manage.py createsuperuser
```

Миграции, начальные стили и лимиты создаются автоматически при старте web. `seed_demo` в продакшене запускать нельзя. Caddy выпускает сертификат и обслуживает HTTPS; снаружи публикуются только порты 80 и 443. PostgreSQL, Redis и Gunicorn доступны во внутренней сети Compose. Заголовки прокси доверяются только при такой схеме сети: не открывайте web:8000 наружу при `TRUST_PROXY_HEADERS=1`.

Войдите администратором на `/admin/`, создайте пользователя преподавателя, добавьте его в группу **«Преподаватели»**. Для управления шаблонами через админку дополнительно нужны `is_staff` и соответствующие разрешения. Преподаватель создаёт учеников на странице «Ученики». Восстановление паролей и блокировка аккаунтов выполняются администратором через Django Admin; ученик может самостоятельно сменить известный пароль.

Это одна организация: преподаватели видят все заявки центра. Изоляция разных центров и разграничение по классам не реализованы.

## Нагрузка и справедливая очередь

Целевой размер группы — около **10 одновременно работающих учеников**. По умолчанию разрешено **10 одновременных генераций Meshy**; преподаватель может снизить этот лимит, но не поднять выше 10 через интерфейс.

На ученика допускается **только одна незавершённая заявка**. Ограничение действует уже с момента отправки на проверку и сохраняется во время ожидания очереди, отправки, генерации, сохранения и ручной сверки неоднозначной отправки. После готовности модели, возврата преподавателем или окончательной ошибки можно отправить следующую идею.

Это не только проверка интерфейса: сервер блокирует строку пользователя при создании, а частичный UNIQUE-индекс PostgreSQL запрещает вторую незавершённую заявку на того же ученика даже при запросах из нескольких вкладок. Старые завершённые проекты остаются доступны для скачивания.

Очередь **FIFO по времени одобрения**. Даже если сообщения Celery пришли не по порядку, обработчик не даст новой заявке опередить более старое одобрение. Один ученик занимает максимум один слот. Число процессов Celery не равно числу генераций Meshy: API асинхронный, поэтому два фоновых процесса могут запустить и отслеживать десять внешних генераций. Файлы сохраняются ограниченным числом процессов, чтобы не расходовать память сервера на десять больших загрузок одновременно.

Для старта с 10 учениками разумная конфигурация собственного сервера: 2–4 CPU, 4 ГБ RAM, SSD с резервом под модели. Это оценка для пилота; нагрузочное испытание на целевом сервере и замеры реальных размеров моделей ещё нужны. Ограничение 10 одновременных задач провайдера само по себе не задаёт пропускную способность по кредитам и скорости HTTP-запросов.

## Экспорт в Unity 6 3D URP

Основной формат скачивания — **FBX**. В интерфейсе две кнопки: «Скачать FBX» и «FBX + текстуры · ZIP». GLB используется только внутри браузерного 3D-просмотра. STL не запрашивается и не предлагается.

ZIP содержит файл FBX, все доступные карты base color / normal / metallic / roughness / emission, индекс наборов материалов и русскую инструкцию импорта. Для metallic + roughness автоматически готовится карта для URP/Lit: R = metallic, A = 1 − roughness, G = 1, B = 0. Импортируйте такую карту с отключённым sRGB. Нормали импортируются как Normal map. Base Color использует sRGB.

FBX задаёт геометрию и переносимые материалы; привязка к шейдеру `Universal Render Pipeline/Lit` выполняется в Unity. Проект не обещает, что импортированный FBX автоматически получит корректные URP-материалы. Гайд внутри ZIP объясняет создание и назначение материалов и проверку масштаба. Это обычный ZIP, не `.unitypackage`. Сам импорт в установленный Unity Editor в этой среде не проверялся.

В демо выдаётся валидный ASCII FBX 7.4 с учебным кристаллом, совпадающим с GLB-превью. Демо-кристалл без UV/PBR — для него достаточно однотонного материала URP/Lit. Реальные FBX и карты берутся из соответствующей задачи Meshy. При обновлении старого локального демо команда `seed_demo` добавляет FBX и ZIP готовым демо-заявкам без вызовов API.

[Каналы упакованной карты URP](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/shaders-in-universalrp-channel-packed-texture.html), [URP/Lit](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/lit-shader.html).

## Надёжность очереди

```text
На проверке ── возврат с причиной ──> Нужны изменения
     │
     └─ одобрение ─> В очереди ─> Отправляем ─> Генерация ─> Сохранение ─> Готово
                                    │             │
                                    │             └─ провайдер отклонил ─> Ошибка
                                    └─ ответ потерян ─> Проверка отправки
```

- Источник истины — запись в PostgreSQL, а не сообщение Redis. Celery Beat каждые 15 секунд поднимает подходящие записи, включая потерянные после перезапуска worker.
- Одобрение, квота и резервирование параллельных задач защищены транзакциями и блокировками. Повторный клик не переодобряет заявку.
- POST Meshy не повторяется автоматически. Timeout, неоднозначный ответ или прерванная отправка переводят заявку в ручную сверку. Без подтверждённого Meshy task ID система не может гарантировать, что провайдер не списал кредиты.
- Преподаватель сверяет фото, время и API-историю Meshy. Если задача существует, привязывает её ID; если достоверно отсутствует, закрывает отправку как ошибку. Это не создаёт повторную платную задачу. Для новой генерации нужна новая заявка и новое одобрение.
- Неопределённые отправки занимают слот параллельной генерации до сверки. Так ошибка сети не запускает бесконтрольные новые задачи.
- GET статуса и сохранение результата повторяются с задержкой до 15 минут. Временная ошибка не удаляет Meshy task ID. При долгой недоступности ребёнок и преподаватель видят сообщение, заявка остаётся в работе для восстановления.
- Только после сохранения FBX, ZIP с текстурами и GLB для внутреннего предпросмотра в своём хранилище модель получает статус «Готово». Срок хранения ресурсов Meshy ограничен: длительные сбои требуют внимания преподавателя до истечения `expires_at`. Автоматическое повторное создание оплачиваемой модели не выполняется.
- Снятие флага «Разрешить отправку» останавливает новые отправки, но позволяет завершить и сохранить уже начатые задачи.
- Уведомления встроены в личный кабинет: история событий и проверка изменения статуса каждые 8 секунд при открытой вкладке. Email, Telegram и push при закрытом браузере не подключены.

## Данные и доступ

Регистрация детей закрыта. Ученик видит только собственные заявки и файлы, включая прямые URL скачивания. Фото перекодируются в JPEG до 2048×2048 с удалением EXIF/GPS; принимаются JPG/PNG/WebP до 10 МБ и 20 мегапикселей. Для фото отсутствует публичный `/media/`-маршрут. Сессии, CSRF, безопасные cookie при HTTPS и ограничение попыток входа включены. Встроенная проверка контента Meshy дополняет решение преподавателя.

Файлы Meshy скачиваются потоково с ограничением размера, только по HTTPS с разрешённых доменов хранилища, без пересылки API-ключа и без HTTP-переадресаций. Если провайдер меняет домен хранилища, администратор проверяет адрес и меняет `MESHY_ASSET_HOSTS` в окружении.

Вход и отправка фото зависят от учётной записи центра. До использования с детьми центр определяет допустимые материалы и согласования, срок хранения фото, порядок удаления и резервного копирования. Автоматическое удаление по сроку, выгрузка согласий и многопользовательская организация разных центров в эту версию не входят. Резервные копии нужно делать для PostgreSQL **и** volume `media`; при восстановлении нужны обе части. Отдельный объектный storage S3/R2 можно подключить через стандартный Django `STORAGES`.

## Проверка

```text
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test
python manage.py collectstatic --noinput
```

Тесты проверяют весь демо-сценарий, права и CSRF, закрытые файлы, возврат с причиной, квоты, повторную доставку задания, потерянный ответ POST, восстановление статуса, фиксацию промпта, сохранение файлов и вход. Внешние платные вызовы в тестах замоканы. Workflow GitHub Actions использует PostgreSQL и Redis.

Проверка production-настроек:

```text
docker compose exec web python manage.py check --deploy
docker compose logs --tail=100 web worker beat
```

Жизнеспособность web: `/health/`. Мониторинг очереди, резервное копирование, ротация секретов и контроль свободного диска должны быть настроены на сервере центра. Docker-образ и миграции следует проверить на целевом сервере перед реальной работой с детьми.

## Структура

```text
config/                 окружение Django и Celery
studio/models.py        заявки, стили, лимиты, история
studio/services.py      транзакции подачи и одобрения
studio/provider.py      Meshy API, сохранение результата, генератор демо-GLB
studio/tasks.py         состояния очереди и восстановление
studio/views.py         кабинеты и закрытая выдача файлов

templates/, static/     интерфейс и локальный 3D-компонент
compose.yaml            сервер, PostgreSQL, Redis, worker, beat, HTTPS
```
