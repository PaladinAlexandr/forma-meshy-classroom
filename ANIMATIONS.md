# Тип модели и анимация

При создании проекта ученик выбирает **гуманоид / животное / предмет**.
Анимация доступна **только гуманоиду**, после завершения создания 3D-модели.
У животных и предметов нет анимации; ограничения проверяются формами, сервисом
создания заявки, одобрением и API-клиентом на сервере.

## Путь ученика и преподавателя

1. Ученик создаёт гуманоидную модель обычным способом, с одобрением преподавателя.
2. После готовности на странице проекта появляется выбор движений:
   **ожидание, ходьба, бег**. Можно выбрать от одного до трёх движений.
3. Кнопка «Отправить анимацию на проверку» возвращает проект преподавателю.
   До одобрения API не вызывается и кредиты не расходуются.
4. Преподаватель видит выбранные движения и может отклонить заявку с комментарием
   или разрешить подготовку скелета и выбранных анимаций. Одобрение разрешает оба
   этапа; каждый из них расходует кредиты Meshy. За каждое выбранное движение
   Meshy начисляет отдельную стоимость. Приложение не обещает фиксированную цену.
5. После одобрения сервер вызывает Rigging API. Когда скелет готов, анимация
   возвращается в общую очередь, пропуская более ранние одобренные заявки.
   Второе решение преподавателя между скелетом и движениями не требуется.
6. Готовые результаты доступны ученику: анимированный **FBX**, ZIP для Unity 6 URP,
   просмотр и переключение клипов в браузере. Исходные FBX и текстуры сохраняются.
   ZIP включает animation.fbx, original-model.zip с исходной моделью/текстурами
   и UNITY-ANIMATION.txt с инструкцией импорта.

Можно запросить другие движения позже, снова с одобрением преподавателя.
Приложение повторно использует сохранённый скелет. Предыдущие готовые анимации
остаются доступны во время новой генерации. При ошибке или отклонении анимации
исходная модель по-прежнему доступна для скачивания.

## Очередь и восстановление

У ученика может быть только один незавершённый проект, включая анимацию.
Если он уже начал другой проект, анимацию старого начать нельзя. Во время ожидания
одобрения, риггинга, генерации, сохранения и неопределённого результата отправки
создать новый проект нельзя. Проверка сериализуется блокировкой строки ученика
и ограничением PostgreSQL, включая одновременные запросы из разных вкладок.

Картинки, 3D-модели, риггинг и анимации используют общий лимит до **10** активных
задач; резервирование слота защищено блокировкой строки настроек центра.
Риггинг и анимация одного ученика выполняются последовательно. Неопределённая
отправка сохраняет резерв до сверки преподавателем. Месячный лимит одобрений
считает проекты; новые этапы одного проекта не учитываются как новые проекты.
Анимации контролируются отдельным одобрением преподавателя, а не автоматическим
бюджетом кредитов. Фактические кредиты модели, скелета и каждого набора движений
отображаются раздельно, если их вернул Meshy.

Платные POST-запросы автоматически не повторяются после таймаута или аварии.
Преподаватель сверяет текущий этап и ID задачи через существующий блок
«Сверка с Meshy». Ошибки скачивания повторяют GET и сохранение, а не генерацию.

## Требования Meshy и API

Выбор типа не гарантирует успешную анимацию: нужен текстурированный гуманоид
с двумя хорошо различимыми руками и ногами. Готовьте изображение в T/A-позе,
с отделёнными от корпуса руками и видимыми ногами. Meshy также ограничивает
сложность модели (сверяйте текущие требования по ссылке ниже).

- `POST /openapi/v1/rigging`: `input_task_id` исходной готовой модели,
  `height_meters: 1.7`; сервер сохраняет `rig_task_id` и FBX со скелетом.
- `POST /openapi/v1/animations`: `rig_task_id`, `action_ids` из разрешённого списка:
  `243` (Idle_3), `566` (walking_2), `530` (run_fast_3).
- Для нескольких движений Meshy возвращает один FBX с несколькими именованными
  клипами. GLB используется только для внутреннего просмотра.
- API-ключ остаётся на сервере. Файлы анимаций закрыты проверкой владельца или
  преподавателя; прямой доступ к медиа не открыт.

Источники: [Rigging API](https://docs.meshy.ai/en/api/rigging),
[Animation API](https://docs.meshy.ai/en/api/animation),
[библиотека движений](https://docs.meshy.ai/en/api/animation-library).
Веб-интерфейс Meshy может поддерживать больше типов, чем публичный API;
анимация животных в FORMA отключена.

В демо вместо настоящего персонажа двигается учебный кристалл. В FBX и GLB
есть именованные клипы, но это демонстрация процесса, а не скелет гуманоидной
модели; для него используйте Rig: Generic. Кредиты Meshy не используются.

## Обновить работающий класс

Дождитесь завершения текущих генераций. Сделайте резервную копию по инструкции
GITHUB_SETUP.md. В папке существующего проекта, установленного через Git:

```powershell
.\forma-http.cmd stop
git pull --ff-only
.\START-FORMA-HTTP.cmd
```

Установщик пересоберёт образы и применит миграцию базы автоматически. Обновите
страницу в браузере через Ctrl+F5. Аккаунты, модели и .env.classroom сохраняются.
Не удаляйте Docker volumes. Если приложение было установлено из ZIP, замените
исходные файлы новым архивом обновления и запустите START-FORMA-HTTP.cmd в той же
папке; локальные .env и данные в архив не входят.

У старых проектов, созданных до появления выбора типа, установлен тип «предмет»;
автоматически угадывать анатомию по названию приложение не пытается. Для нового
персонажа выберите «гуманоид» при подаче заявки.
